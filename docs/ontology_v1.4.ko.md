# 로봇 조작 액션 온톨로지 정의서 (v1.4)

## 1. 구성 원칙

**층의 기준.** 층은 "그 라벨을 판정하는 데 필요한 정보가 어디서 오는가"로 나눈다.

| 층 | 판정 정보 | 라벨링 주체 | 집합 |
|---|---|---|---|
| L0 로봇 층 | 로봇 탑재 저수준 센서에서 파생된 신호 (관절·엔드이펙터 상태, 그리퍼 개폐·부하, 베이스 odometry, 힘·촉각 센서). 카메라 불필요 | 규칙 기반 자동 계산 | 닫힘 |
| L1 조작 층 | 카메라로 관측한 로봇과 **객체 하나**의 관계 | 사람 또는 VLM | 닫힘 + `Other` |
| L2 과제 층 | 과제 목표와 지시문 | 사람 또는 VLM | 열림 |

**층 사이의 관계는 구성(part-of)이다.** L1 세그먼트는 연속된 L0 세그먼트들의 스팬이고, L2 세그먼트는 연속된 L1 세그먼트들의 스팬이다. 따라서 상위 층의 경계는 원칙적으로 하위 층 경계의 부분집합이다 (예외는 §3.4-6에 열거).

**층 안의 관계는 분류(is-a)이다.** 같은 층의 클래스는 족(family)으로 묶는다. 족은 분할 단위가 아니라 평가와 병합에만 쓴다.

**클래스와 속성을 분리한다.** 방향, 대상 객체, 회전축, 각도, 지속 시간, 성공 여부처럼 조합을 늘리는 차원은 클래스가 아니라 속성이다. 라벨 형식은 `동사(대상; 속성=값, …)`이다.

## 2. L0 — 로봇 층

L0는 프레임마다 정확히 하나의 상태와 0개 이상의 속성을 가지며, 이벤트가 발생하는 프레임에서 세그먼트가 나뉜다. 어떤 신호가 있느냐에 따라 L0에서 관측 가능한 이벤트 집합이 달라지며, 관측 불가능한 이벤트는 L1의 시각 관측으로 이관된다.

### 2.1 상태

| 상태 | 정의 |
|---|---|
| `Still` | 엔드이펙터와 베이스가 모두 정지 |
| `ArmMove` | 엔드이펙터가 이동 중, 베이스 정지 |
| `BaseMove` | 베이스가 주행 중 (팔의 움직임과 무관) |

### 2.2 이벤트

| 이벤트 | 정의 | 측정 신호 |
|---|---|---|
| `GripClose` | 그리퍼 닫힘이 **개시**되는 시점 | 그리퍼 폭의 감소 시작, 또는 닫힘 명령 전환 |
| `GripCloseDone` | 손가락이 실제로 닫혀 물리적 파지가 성립하는 시점 | 그리퍼 폭이 열림↔닫힘 **중간 문턱**을 지나는 시점 (명령이 아니라 폭) |
| `GripOpen` | 그리퍼 열림이 **개시**되는 시점 | 그리퍼 폭의 증가 시작, 또는 열림 명령 전환 |
| `GripOpenDone` | 손가락이 실제로 벌어져 객체가 놓이는 시점 | 그리퍼 폭이 **중간 문턱**을 지나는 시점 |
| `SupportOff` | 파지한 객체가 받침면을 떠남 | 손목 F/T 수직 하중 증가, 그리퍼 촉각·부하 변화, 또는 `GripClose` 완료 후 첫 `dz=up` 전환(운동학 근사) |
| `SupportOn` | 파지한 객체가 받침면에 닿음 | 수직 하중 감소, 또는 `GripOpen` 직전 마지막 `dz=down` 종료(운동학 근사) |
| `ContactOn` / `ContactOff` | 엔드이펙터 또는 파지물이 외부 객체·표면과 접촉을 시작/소실 | 힘·촉각 센서. 없으면 L0 이벤트가 아니며 L1에서 시각 관측 |

**어느 이벤트를 쓰는가 — 경계는 전이의 개시에 둔다 (v1.4, 문턱 훑기로 재교정).**
**모든 경계는 전이가 처음 관측되는 순간에 둔다.** 완료 시점(`...Done`)은 속성이지 경계가 아니다. v1.3은 "시작=개시, 끝=완료"라고 적었으나 문턱 훑기 결과 `Place` 끝도 **열림 개시**에 붙는 것으로 나왔다(최적 폭 문턱 f=0.05, 중앙 |Δ| 0.10초, 0.2초 이내 27/28; 중간 문턱 f=0.5는 0.40초·0.077). `Move`→`Grasp`도 같다(f=0.9 = 닫히기 시작, 중앙 0.10초, 26/31). 즉 **사람은 손가락이 움직이기 시작하는 순간에 경계를 긋는다.** `Grasp` 끝(`SupportOff`, 물체가 받침을 떠나는 첫 순간)도 같은 원리다 — 셋 다 "변화가 처음 보이는 순간"이다.

| 경계 | 쓰는 이벤트 | 중앙 편차 | 0.2초 이내 |
|---|---|---:|---:|
| `Move`→`Grasp` | 닫힘 개시 (폭 f≈0.9) | 0.10초 | 26/31 |
| `Grasp` 끝 | `SupportOff` | 0.10초 이하 | 20/31 |
| `Place` 끝 | 열림 개시 (폭 f≈0.05) | 0.10초 | 27/28 |

문턱 값 f는 30편·1인 자료에서 고른 값이므로 **보정치이지 확정 상수가 아니다**(따로 떼어 둔 자료로 확인 전까지). v1.3의 폐기된 문장: "구간의 시작은 개시 이벤트, 구간의 끝은 완료 이벤트를 쓴다."
 v1.2는 "명령이 아니라 물리 사건을 쓴다"고만 했는데, 사람 세밀 라벨 30편(LIBERO-Object)과 대조한 결과 그 규칙은 종결 경계에서만 맞았다. 측정값(부호 = 사람 − 이벤트):

| 사람 경계 | 이벤트 | 중앙 | 0.2초 이내 |
|---|---|---:|---:|
| `Move`→`Grasp` (시작) | `GripClose`(개시) | **+0.10초** | 27/31 |
| 〃 | `GripCloseDone`(완료) | −0.40초 | 3/31 |
| `Grasp` 끝 | `SupportOff` | **+0.00초** | 20/31 |
| `Place` 끝 | `GripOpen`(개시) | +0.50초 | 0/30 |
| 〃 | `GripOpenDone`(폭 중간 문턱) | −0.40초 | 2/26 |

사람은 손가락이 움직이기 시작하는 순간에 `Grasp`를 시작하므로 시작 경계는 **개시** 이벤트에 붙는다. 반대로 `Grasp` 끝은 완료 사건(`SupportOff`)과 중앙 0.00초로 일치한다.

**(v1.3 기록) 미해결이었던 `Place` 끝의 문턱 — v1.4에서 열림 개시로 확정.** 사람은 열림 개시와 완료의 **사이**(개시 +0.50초, 중간 문턱 −0.40초)에 찍는다. 현재 규정인 중간 문턱(0.5)은 0.4초 늦다. 거친 창(±0.5초)에서는 26/26으로 맞지만 0.2초에서는 2/26이다. **문턱 값은 실측으로 보정할 자리이며, 그 전까지 `GripOpenDone`을 잠정 기준으로 둔다.**

**명령과 물리 사건의 구분(v1.2).** `GripClose`/`GripOpen`은 개시 시점이고 `GripCloseDone`/`GripOpenDone`은 완료 시점이다. 두 시점은 같지 않으며 간격은 플랫폼에 따라 다르다 (LIBERO 10 fps 자료에서 `GripClose`→`SupportOff` 중앙 6프레임 = 0.6초). **세그먼트 경계로는 물리 사건을 쓴다.** 명령 시점을 경계로 쓰면 실제 사건보다 일정하게 앞서고, 그 앞섬이 허용 오차보다 작을 때 다른 사건을 맞힌 것으로 오인된다. 중간 문턱은 그 에피소드에서 관측된 열림 폭 최대와 닫힘 폭 최소의 중간값으로 정한다.

### 2.3 속성

| 속성 | 값 | 정의 |
|---|---|---|
| `holding` | 0 / 1 | 그리퍼가 객체를 파지하고 있는가 (그리퍼 폭·부하) |
| `dz` | up / down / flat | 엔드이펙터 수직 속도의 부호 |
| `contact` | 0 / 1 | 외부 접촉 여부 (센서 없으면 결측) |
| `base` | 0 / 1 | 베이스 주행 여부 |

### 2.4 파생 셀

상태와 `holding`의 조합으로 네 가지 셀이 정의된다. 셀은 라벨이 아니라 조합의 이름이다.

| | holding=0 | holding=1 |
|---|---|---|
| `Still` | Idle | Hold |
| `ArmMove` | FreeMove | HeldMove |

### 2.5 L0 경계 규칙

세그먼트는 다음에서만 나뉜다: 상태 전환, 이벤트 발생, `holding` 변화. 팔의 방향 전환이나 속도 변화만으로는 나뉘지 않는다.

## 3. L1 — 조작 층

L1 세그먼트는 하나의 동사와 하나의 대상 객체를 갖는다.

### 3.0 구간 규약 — 어디서 끊는지는 온톨로지가 아니라 규약이 정한다

클래스 집합(무엇이라 부르는가)과 구간 규약(어디서 끊는가)은 별개의 결정이다. 같은 온톨로지로 같은 영상을 보고도 접근 이동을 `Grasp`에 포함하느냐 별도 `Move`로 두느냐에 따라 구간이 달라진다. 따라서 규약을 선언하지 않은 라벨은 다른 라벨과 비교할 수 없다. 이 문서는 두 규약을 정의하고, 기본값으로 **세밀 규약**을 쓴다.

| | 세밀 규약 (본 문서 기본) | 흡수 규약 |
|---|---|---|
| 접근 이동 | 독립 `Move(holding=0, relation=toward)` | 뒤따르는 `Grasp`에 포함 |
| 운반 이동 | 독립 `Move(holding=1)` | 뒤따르는 `Place`에 포함 |
| 복귀·후퇴 이동 | 독립 `Move(relation=away)` | 독립 `Move` (두 규약 동일) |
| `Grasp` 범위 | `GripClose` ~ `SupportOff` | 접근 시작 ~ `SupportOff` |
| `Place` 범위 | 하강 시작 ~ `GripOpenDone` | 운반 시작 ~ `GripOpenDone` |
| D~G족 범위 | 접촉 구간만 | 접근·복귀 포함 |

**세밀 → 흡수는 결정론적으로 내려갈 수 있고, 역은 불가능하다.** 아래 규칙은 정보를 잃지 않고 적용된다: `Grasp` 바로 앞의 `Move`·`Idle`을 그 `Grasp`에 흡수 · `Place` 바로 앞의 `Move`를 그 `Place`에 흡수 · `Place` 뒤의 `Move`(후퇴)는 유지 · 같은 라벨의 인접 구간 병합. 반대로 흡수 규약 라벨에서 접근과 파지의 경계를 되살리려면 원래 신호나 영상을 다시 봐야 한다. 그러므로 **라벨은 세밀 규약으로 만들고, 비교할 때 필요한 쪽으로 투영한다.**

두 규약의 이름을 라벨 파일의 `Convention` 필드에 기록한다 (`fine` / `absorb`).

### 3.1 클래스 정의

**A족 — 획득** (객체가 로봇의 파지 상태로 들어옴)

| 클래스 | 정의 | 시작 | 종료 |
|---|---|---|---|
| `Grasp` | 그리퍼가 객체를 닫아 잡고 받침에서 들어올림 | `GripClose` 시작 | `SupportOff` |

**B족 — 방출** (객체가 로봇의 파지 상태에서 나감)

| 클래스 | 정의 | 시작 | 종료 |
|---|---|---|---|
| `Place` | 파지한 객체를 목적지에 내려놓고 놓음 | 목적지를 향한 하강 시작 | `GripOpenDone` (손가락 열림이 중간 문턱을 지나는 시점) |
| `Insert` | 파지한 객체를 구멍·슬롯·구속된 끼움 위치에 넣음 | 삽입 축 정렬 시작 | 삽입 완료 (그리퍼는 열릴 수도 유지될 수도 있음) |

**C족 — 이동·대기** (객체 상태 변화 없음)

| 클래스 | 정의 | 시작 | 종료 |
|---|---|---|---|
| `Move` | 객체 상태 변화 없이 엔드이펙터가 이동 | 직전 세그먼트 종료 | 다음 A/B/D~G 세그먼트 시작 |
| `Navigate` | 베이스가 주행하여 로봇 전체를 이동 | 베이스 주행 시작 | 베이스 주행 정지 |
| `Hold` | 객체를 파지한 채 엔드이펙터가 정지 | 정지 시작 | 이동 재개 |
| `Idle` | 객체를 파지하지 않고 접촉 없이 정지 | 정지 시작 | 이동 시작 |

**D족 — 비파지 접촉** (파지 없이 접촉으로 객체에 작용)

| 클래스 | 정의 | 시작 | 종료 |
|---|---|---|---|
| `Push` | 접촉을 유지하며 객체를 엔드이펙터 진행 방향으로 변위 | 접촉 시작 | 접촉 소실 |
| `Pull` | 접촉을 유지하며 객체를 로봇 쪽으로 변위 | 접촉 시작 | 접촉 소실 |
| `Slide` | 접촉을 유지하며 객체를 표면을 따라 변위 (Push/Pull로 방향을 특정할 수 없을 때) | 접촉 시작 | 접촉 소실 |
| `Press` | 접촉 지점에 힘을 가하되 객체를 변위시키지 않음 | 접촉 시작 | 접촉 소실 |

**E족 — 재배향** (객체의 자세 변화가 지배적)

| 클래스 | 정의 | 시작 | 종료 |
|---|---|---|---|
| `Rotate` | 객체의 방향을 바꿈 (파지 여부 무관) | 회전 시작 | 회전 정지 |
| `Align` | 다른 객체·기준에 맞춰 객체의 위치·자세를 미세 조정 | 조정 시작 | 조정 정지 |

**F족 — 구조 상태 변화** (관절·변형·결합 객체의 상태가 바뀜)

| 클래스 | 정의 |
|---|---|
| `Open` / `Close` | 문·뚜껑·서랍 등 관절 객체를 열림/닫힘 상태로 전환 |
| `Fold` / `Unfold` | 천·종이 등 변형 객체를 접힘/펼침 상태로 전환 |
| `Zip` / `Unzip` | 지퍼를 잠금/해제 상태로 전환 |
| `Remove` | 삽입·덮임·부착된 객체를 그 상태에서 분리 |

F족의 시작은 객체 상태 변화의 시작(또는 그 직전의 접촉 시작), 종료는 상태 변화의 완료(또는 접촉 소실)이다.

**G족 — 표면·재료 효과** (객체 또는 도구로 표면·재료에 작용)

| 클래스 | 정의 |
|---|---|
| `Wipe` | 표면 위에서 왕복 접촉 |
| `Brush` | 도구로 표면을 한 방향으로 쓸어냄 |
| `Sweep` | 흩어진 재료를 한 곳으로 모음 |
| `Pour` | 용기를 기울여 내용물을 다른 곳으로 옮김 |
| `Shake` | 파지한 객체를 반복 진동시킴 |

G족의 시작은 효과가 시작되는 접촉 또는 기울임의 시작, 종료는 그 소실이다.

**기타**

| 클래스 | 정의 |
|---|---|
| `Other` | 위 어느 클래스에도 해당하지 않는 실제 동작. 원래 명칭을 `Unmapped` 필드에 기록 |

정본 클래스는 총 **25종** (A 1 + B 2 + C 4 + D 4 + E 2 + F 7 + G 5), `Other`는 별도. 개수는 대상 데이터셋의 사람 라벨을 손실 없이 수용하기 위한 것이며 완전성을 주장하지 않는다. 구조의 단위는 개수가 아니라 7족이다.

### 3.2 속성

| 속성 | 값 | 적용 클래스 |
|---|---|---|
| `target` | 객체 ID | 전 클래스 (Idle 제외) |
| `holding` | 0 / 1 | Move, Navigate, Rotate, Press |
| `dz` | up / down / flat | Move |
| `relation` | toward / away / none | Move (특정 대상에 대한 접근·이탈) |
| `axis` | self / vertical / horizontal | Rotate |
| `angle` | 도 | Rotate |
| `pose_to` | upright / fallen / inverted | Rotate |
| `duration` | short / sustained | Press |
| `controlled` | true / false | Place (false = 공중에서 놓음) |
| `tool` | 객체 ID | Brush, Sweep, Wipe, Pour |
| `success` | true / false | 전 클래스 |

### 3.3 파생 표기

속성 조합에 이름이 필요할 때만 쓰는 별칭이다. 클래스가 아니며, 정본 라벨은 항상 클래스+속성이다.

| 별칭 | 정본 표기 |
|---|---|
| `Lift` | `Move(holding=1, dz=up)` |
| `Lower` | `Move(holding=1, dz=down)` |
| `Carry` | `Move(holding=1, dz=flat)` |
| `Reach` / `Approach` | `Move(holding=0, relation=toward)` |
| `Retract` | `Move(relation=away)` |
| `Tap` | `Press(duration=short)` |
| `Turn` | `Rotate(axis=vertical)` |
| `Twist` | `Rotate(axis=self)` |
| `Flip` | `Rotate(pose_to=inverted)` |
| `Upright` | `Rotate(pose_to=upright)` |
| `Topple` | `Rotate(pose_to=fallen)` |
| `Drop` | `Place(controlled=false)` |
| `Pick` / `Take` | `Grasp` |
| `Put` / `Release` | `Place` |

### 3.4 L1 경계 규칙 (L0 → L1 구성)

1. `GripClose` 직후의 HeldMove(dz=up) 구간은 `Grasp`에 포함한다. `Grasp`의 시작은 `GripClose`, 종료는 `SupportOff`이며, 세밀 규약에서 그 앞의 접근 이동은 `Grasp`에 포함하지 않는다.
2. `GripOpen` 직전의 HeldMove(dz=down) 구간은 `Place`에 포함한다. 이 하강 시작점은 `holding=1`에서 `dz`가 down으로 전환된 뒤 `GripOpen`이 뒤따르는 첫 시점으로 정한다. `Place`의 종료는 `GripOpenDone`이다.
3. 세그먼트 동안 객체의 상태 변화가 관측되면 D~G족의 동사로 라벨한다. 세밀 규약에서 그 **직전 접근 이동과 직후 복귀 이동은 같은 세그먼트에 포함하지 않으며** 각각 `Move`다 (흡수 규약에서는 포함한다, §3.0).
4. 1~3에 해당하지 않는 ArmMove는 `Move`, BaseMove는 `Navigate`, Still은 `Hold`(holding=1) 또는 `Idle`(holding=0)이다.
5. 같은 라벨의 인접 세그먼트는 병합한다.
6. L1 경계는 L0 경계의 부분집합이어야 한다. 예외는 다음과 같다.
   - **`Place` 시작점 — 실측으로 "복원 불가" 확인 (v1.3).** 사람 세밀 라벨 30편과 대조한 결과, 이 경계를 0.5초 안에 맞히는 신호 대리값이 하나도 없다: `place_onset` 앵커 0/29, 물체 z 최고점·엔드이펙터 z 최고점 각각 6/30(중앙 +1.10초). 다만 방향은 일관된다 — 사람은 **30/30에서 물체 높이 최고점 이후** +0.3~+2.8초에 찍는다(호의 꼭대기가 아니라 하강이 확실해진 뒤). 또한 `place_onset` 앵커 자체가 신뢰할 수 없다(물체 z 최고점 대비 19편 2~24프레임 앞, 10편 21~45프레임 뒤) → **앵커 목록에서 폐기한다.** 이 경계는 `dz` 전환과 뒤따르는 `GripOpen`을 함께 해석해야 정해진다. Grasp–Move–Place 골격의 네 경계(`GripClose`, `SupportOff`, Place 시작, `GripOpenDone`) 중 이산 L0 이벤트에 앵커되지 않는 것은 이것뿐이다. 나머지 셋은 모두 물리 사건에 앵커된다.
   - **`Insert` 시작점**: 삽입 축 정렬의 시작은 시각 관측이다.
   - **D~G족의 시작·종료**: `ContactOn/Off`가 L0에 있을 때(힘·촉각 센서)만 L0 앵커이고, 없으면 시각 관측이다. 객체 상태 변화의 시작·완료(F족) 자체는 항상 시각 관측이다.

### 3.5 판정 순서

한 L0 구간 묶음에 대해 다음 순서로 묻고 처음 해당하는 것을 택한다.

1. 베이스가 주행하는가 → `Navigate`
2. 이 구간에서 객체의 구조 상태가 바뀌는가 → F족
3. 표면·재료 효과가 일어나는가 → G족
4. 파지 없이 접촉으로 객체가 변위하거나 힘을 받는가 → D족
5. 객체의 자세 변화가 지배적인가 → E족
6. `GripClose`를 포함하는가 → `Grasp`
7. `GripOpen`을 포함하는가 → `Place` 또는 `Insert`
8. 엔드이펙터가 정지인가 → `Hold` / `Idle`
9. 그 외 → `Move`
10. 실제 동작이지만 어디에도 없음 → `Other`

두 클래스가 모두 해당하면 순서가 앞선 것을 택한다.

## 4. L2 — 과제 층

L2 세그먼트는 연속된 L1 세그먼트들이 달성하는 하위 목표다. 형식은 `목표명(대상; 출발→도착)`이며 집합은 열려 있다.

| 예 | L1 구성 |
|---|---|
| `pick-and-place(cup; table→shelf)` | Grasp(cup) → Move → Place(cup, shelf) |
| `open-container(box)` | Move → Open(box lid) |
| `pour-into(bottle; bowl)` | Grasp(bottle) → Move → Pour(bottle; bowl) → Move → Place(bottle) |
| `clear-surface(table)` | pick-and-place × n |

제약: L2 경계 ⊆ L1 경계. 하나의 L2는 여러 L1 시퀀스로 실현될 수 있고, 같은 L1 시퀀스가 과제에 따라 다른 L2로 해석될 수 있다.

## 5. 금지 사항

- 팔의 방향 전환이나 속도 변화만으로 세그먼트를 나누지 않는다.
- 파생 표기(§3.3)를 정본 라벨로 쓰지 않는다.
- 같은 층 안에서 서로 다른 층의 기준을 섞지 않는다. 예: L1 세그먼트를 `dz` 변화로 나누지 않는다.
- 의도를 추론하여 라벨하지 않는다. 그리퍼가 닫혔으나 객체를 잡지 못했으면 `Move`이며, 의도는 `success=false`와 설명 필드에 기록한다.
- `Other`에 정본 클래스 이름을 넣지 않는다.
- 구간 규약을 밝히지 않은 라벨을 다른 라벨과 직접 비교하지 않는다 (§3.0).
- 경계에 쓸 이벤트를 뜻과 어긋나게 고르지 않는다: **시작은 개시 이벤트, 끝은 완료 이벤트**(§2.2). 종결 경계에 명령 시점을 쓰지 않는다.
- `place_onset`을 물리 앵커로 쓰지 않는다 (§3.4-6, v1.3에서 폐기).
